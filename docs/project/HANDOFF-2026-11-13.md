## The one thing to know

**The verification gate is the point of this session.** Before it, a deploy ended
at "the switch reported OK" plus a human with a screenshot, and that is not
verification: a working install can look broken (the watcher bounce) and a stale
one can look fine (the compiled-JS cache). `native-install.cjs install` now ends
with four checks and a verdict:

```
PASS  bundle   202880e9… — the expected candidate
PASS  engine   hisenseUI restarted: pid 21543 (was 19464)
PASS  frame    1920x1080, IDAT 340 KB
PASS  watcher  watcher disabled
verify: VERIFIED on 50A51HUV / 09.01O.P0813
```

If it says anything else, read the checks — they name what is actually running.

## What is proven on hardware

- **The deploy path, end to end**, several times: build from the pinned stock,
  upload over the SSH lane (`scp` does not work here), atomic swap, cache reset,
  engine restart, watcher ownership, verification.
- **The native Home renders**: clock, inputs dock with device names, the one
  Apps door, the settings surface, the overlay, the idle screen.
- **Input names come from the TV.** `displayname2`/`deviceName` resolves to
  "PlayStation 5", "Fire TV Stick". Config overrides still win.
- **The device icons paint** — as div shapes (see the engine section).
- **Rollback works**, and the watcher backup is seeded from the pre-native
  config so a rollback restores the canvas-launcher setup correctly.

## What is NOT proven

- **The overlay's new visual treatment** and **the idle screen** are live and
  unverified by eye. Both are claims until someone looks.
- **The action paths**: switching to an input, launching an app from the overlay,
  opening the settings sub-pages. The platform adapter is tested, not observed.
- **`power standby`** refuses rather than guessing, and **wake-from-standby is
  UNMEASURED** on this hardware. Do not script against it.
- **The sinkhole is open.** `drift-check` reports it on every run: AdGuard
  resolves all seven vidaahub telemetry hosts and `dns.google` accepts `:443`.
  The remedy is re-applying the per-client rules in `firmware/ADGUARD_APPLY.md`.
  Nobody has done it because it is a firewall change on the owner's TV.

## What this engine will and will not paint

The expensive finding, in
[findings 13 §8](../models/50A51HUV/09.01O.P0813/findings/13-native-home.md):

| Mechanism | Paints? |
| --- | --- |
| SVG data URI in an `<img>` | **no** |
| the same SVG in `background-image` | **no** |
| the vendor icon-font class the SDK reports | **no**, outside vendor components |
| a PNG data URI in `background-image` | yes (the wallpaper) |
| a `div` with a border or background | yes |

So: raster or shapes, never SVG, and do not count on the vendor icon font from an
injected component. The dock's device icons are div shapes for that reason.

## Operating it

```sh
# is the TV reachable, and what is wrong if not
node tools/launcher-host/native-install.cjs doctor --model 50a51huv --host 192.168.0.175

# what is on the TV, and has anything drifted
node tools/launcher-host/native-install.cjs status --model 50a51huv --host 192.168.0.175

# deploy (builds, uploads, switches, verifies, owns the watcher)
node tools/launcher-host/native-install.cjs install alvidaa --model 50a51huv --host 192.168.0.175

# back to stock
node tools/launcher-host/native-install.cjs rollback --model 50a51huv --host 192.168.0.175

# review a layer in a browser instead of on the TV
node tools/launcher-host/preview-native-home.cjs --port 8123
#   /  /?view=overlay  /?view=settings  /?view=settings-apps

# snapshot the mutable state before touching anything
./tools/alvidaa backup --out ~/alvidaa-backups
```

## Traps, in the order they bit

1. **`git checkout <pr> -- <dir>` is a silent revert.** It copies the branch's
   whole directory, including files the branch never touched, from a base that
   may be old. Merging PR #65 that way reverted seven files (~2,500 lines:
   the settings surface, the device shapes, the watcher ownership). Take a PR's
   *changed* files, never a directory.
2. **`git diff main..HEAD` conflates two things.** It shows how far `main` has
   moved as well as what the branch changed, so an old base looks like a dirty
   branch. Use `git diff --stat main` as the *staleness* gate (any file that is
   not yours means rebase) and `git diff --stat $(git merge-base main HEAD)..HEAD`
   for commit hygiene. Both, in that order.
3. **The SDK and the MQTT sourcelist name the same fact differently.**
   `all-inputs.getAllInputsData` reports `deviceName`; the sourcelist the bridge
   reads calls it `displayname2`. The native lane only sees the SDK.
4. **`box()` always emits `position: absolute`,** so a panel built with it is the
   containing block for its children. Positioning a child at `panelX + 56` inside
   a panel at `panelX` double-counts the offset.
5. **The TV closes SSH for a second or two around every engine restart.** The
   watcher sync and the deploy's own reads must retry; a transient drop is not a
   failure.
6. **`id`, `curl`, `wget`, `nc`, `sha256sum` and `df` do not exist on this
   build.** `md5sum`, `sed`, `awk`, `grep`, `head`, `sleep`, `ps`, `ls` and
   `/usr/local/bin/busybox` do.
7. **The HAL capture takes 6–8 s.** Poll for the file; a black frame during a
   restart is not proof of a black screen.
8. **Two macOS-only test failures were masking real ones.** The operation-lock
   tests read `/proc/sys/kernel/random/boot_id`. They now skip with a reason off
   Linux, and the gate has been 0-fail since.

## What the tooling now guarantees

Every write path refuses before it writes: `never-touch.json` holds the hard
rules as data with a typo guard, `backup` refuses key material, `restore` refuses
read-only targets and mid-switch states, `reboot` refuses without the kill-switch
check, and `install` records the pre-install state on the host and verifies the
result. Reversibility is still the design law; it is now enforced rather than
described.
