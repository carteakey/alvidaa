## Traps that cost time

- **odin dedupes relaunches by URL path, not query.** A same-path re-open with
  different params keeps the old instance running, so cache-busting with `?v=N`
  silently does nothing. Use a different filename, or a throwaway `&v=N` per
  open, and check the served bytes rather than trusting the reload.
- **A running process keeps the old binary.** Copying a new build over the path
  does not affect the process already running it. `ps` the start time before
  concluding a deploy worked.
- **Herdr team members are bound to `host + session + workspace + pane`.** If any
  of those changes — app restart, workspace switch, pane closed — every wake is
  held forever with no error. Filed as `carteakey/herding#35`. Fix: reopen the
  panes and re-register; the member gets a new id.
- **The bulletin list used to default to the oldest page** (`herding#14`, fixed).
  If a worker seems to have missed something before that fix, it probably did.
- **`/api/sources` is filtered.** It only shows the fields we chose to keep, so it
  cannot answer "does this build publish a device name". Use `?raw=1`.

## Dead ends, and how dead

Both documented in `launcher/README.md`. Neither is proven impossible — do not
close the door on them, just know where the last attempt stopped.

- **Live input preview** — the capability exists on the device (the source menu
  draws it), but it is native video pipeline. The vendor launcher bundle has no
  preview/thumbnail/snapshot API. Not yet audited: `tvinfo`, the FaaS services,
  `/proc` for a capture device.
- **Audio capture / librespot** — measured dead through ALSA on this model: every
  PCM reports `closed` during playback, optical or internal. One untested path:
  odin declares `--alsa-output-device`, so a web page might open a PCM a native
  app does not.

## Vendor disclosure

`VIDAA-PSIRT-2026-005`. Full record in [`docs/DISCLOSURE.md`](../DISCLOSURE.md)
and in Forge. Short version: they acknowledged the report, said the root path was
known to them earlier and is fixed on most devices, and asked for the repo to go
private. The repo stays public; the write-up was toned down to findings rather
than recipes; real device identifiers were scrubbed.

If they follow up with a CVE or a fix timeline, annotate the findings and link it.
